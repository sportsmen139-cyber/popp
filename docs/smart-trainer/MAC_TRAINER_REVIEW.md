# Проверка упражнений на Mac — Stage 3B

## Открыть интерфейс

В Finder открой папку репозитория и дважды нажми **Trainer Review.command**.
Откроются Terminal и браузер. Окно Terminal оставь открытым на время проверки.
Обычный адрес — **http://127.0.0.1:5188/**, точная ссылка напечатана в Terminal.
Это интерфейс на этом Mac. Telegram, Supabase, Node и облачные ключи для проверки
не нужны. Решения не публикуют программу и не подключают её к Training Engine.

Нужен Python 3.12 или новее. Launcher проверяет версию и объясняет, если доступен
только системный Python 3.9. На восстановленном Mac уже подготовлен отдельный
приватный Python в `.local/smart-trainer/python/`; системный Python не менялся.
В новом checkout можно установить Python с [python.org](https://www.python.org/downloads/macos/).
Launcher ничего не скачивает и не устанавливает. Если Finder не запускает файл,
доступен обычный запуск из Terminal, из папки репозитория:

```sh
"./Trainer Review.command"
```

Для нестандартного расположения Python:

```sh
POPP_PYTHON='/полный/путь/python3.12' "./Trainer Review.command"
```

Если порт занят, останови прежний сервер через **Control+C** или запусти
`"./Trainer Review.command" --port 0` и открой ссылку с выбранным свободным портом.
При закрытом Terminal ссылка не работает. Повторный запуск сохраняет историю.
Защиту macOS и проверки Host/Origin/CSRF отключать не требуется.

## Если потерян snapshot

Локальные данные не находятся в GitHub. Launcher сначала ищет зарегистрированный
snapshot, а при его отсутствии сообщает **«Требуется оригинальный XLSX»** и на Mac
открывает выбор файла. Выбери оригинал «Умный тренер — архитектура базы и шаблоны
проверки.xlsx». Или передай путь явно:

```sh
"./Trainer Review.command" --source '/полный/путь/Умный тренер.xlsx'
```

Принимается только SHA256
`1919449150c40600c12d719b415ba1792ac331a8d29be2e4c6191f36f18a904a`.
При отсутствии файла, отмене или другом SHA запуск останавливается. Данные не
создаются по памяти. Существующий importer один раз восстанавливает приватные
artifacts из исходных bytes. Отдельный полный аудит не запускается, исторические
публичные отчёты не перезаписываются. При повторном запуске импорт пропускается:
проверяются source/catalog hashes и точный bundle Stage 3.

Если snapshot повреждён или новый bundle отличается от зарегистрированного,
launcher отказывает без перезаписи старых файлов. Для другого XLSX нужна отдельная
проверка версии, а не подмена checksum. Исходник и полные artifacts остаются в
ignored `.local/smart-trainer/`; не добавляй их в Git.

## Проверить десять основных упражнений

1. Введи своё имя в **«Кто проверяет?»**. Открой **«Начать / продолжить основные»**.
   Маршрут показывает десять EX с отдельными статусами, а не общий процент всех
   177 карточек. Повторное открытие продолжает с первого неутверждённого EX.
2. В карточке прочитай **«Что подтвердить тренеру»**, назначения упражнения по
   фазам, технику, ошибки, ограничения, оборудование и исходные строки. Поля
   можно обсуждать, но комментарий не меняет контент XLSX или машинный контракт.
3. Если утверждение заблокировано, нажми **«Проверить следующую зависимость»**.
   Это откроет неутверждённое определение с уже готовыми зависимостями. Прочитай
   его, поставь явное подтверждение и выбери действие. Через **«Вернуться к
   упражнению»** вернись к EX и проверь следующую зависимость. Общие определения
   повторно утверждать не нужно, пока их решения действуют. Пакетное действие
   допустимо только после прочтения явно отмеченного состава; оно не утверждает EX.
4. После зависимостей отдельно утверди само упражнение. Для сомнений выбери
   **«Требуется исправление»** или **«Отклонить»** с комментарием. **«Оставить
   комментарий»** не утверждает карточку. Подтверждение просмотра сбрасывается
   при смене карточки; черновик комментария сохраняется при переходе к зависимости,
   но пропадает при перезагрузке или закрытии страницы.
5. Дождись **«Решение записано…»**, затем открой **«Следующее основное»**. Кнопки
   перехода есть и возле действий внизу карточки. На маршруте проверь итог
   **«утверждено 10 из 10»** либо список оставшихся замечаний. Это результат
   проверки упражнений; отдельная программа может оставаться неутверждённой.

Исходные вопросы по всем EX и программе: [PILOT_TRAINER_REVIEW.md](PILOT_TRAINER_REVIEW.md).
Для EX_000082 и EX_000135 неизвестное оборудование не превращается в пустой kit
после approval или комментария. Эти блокеры будущего выпуска остаются.

## Основная проверка и дополнительные замены

**Обязательный маршрут Stage 3B:** десять основных EX и их обязательные
справочники. Проверка EX не зависит от approvals альтернатив.

**Дополнительный маршрут:** 18 направленных ALT и 18 целевых EX, если нужны замены.
Они находятся в разделах **«Дополнительно»**. Нет автоматического допуска замены
по сходству названия, обратных или транзитивных замен. B требует проверки
контекста, дозы и истории нагрузки. C остаётся изменением программы;
ALT_000476 с другой единицей требует явного typed назначения, а не перевода
повторений в секунды по догадке.

**Полное утверждение программы:** сверь восемь недель, дни 1/3/5, фазы,
подходы/RIR/отдых и правила. Существующий bundle содержит все альтернативы:
для approval всей программы по-прежнему нужны **все включённые зависимости**.
Отложенные замены не считаются разрешёнными. Упрощённого выпуска «без замен»
этот этап не создаёт. Engine, equipment, typed dose, rights и отдельные release
gates сохранены; даже 10/10 не разрешает публикацию.

## Сохранить и восстановить решения

Главный файл:
`.local/smart-trainer/trainer-review/journals/PRG_000002-v1.json`.
Он использует прежний формат append-only истории с source/bundle/record hashes,
версиями, именем, временем и hash chain. Исходные статусы остаются неизменными.
Устаревшее окно получает конфликт: **«Обновить журнал»**, затем проверь состояние
перед повтором. При ошибке записи интерфейс не сообщает об успешном сохранении.

После каждого подтверждённого решения и при запуске с существующим журналом
создаётся отдельная копия в `journals/backups/`. Копии имеют имя с точным journal
head, mode 0600, сохраняются атомарно с fsync и не перезаписываются другим
содержимым. Старые копии остаются. В панели **«Сохранение решений»** есть точные
пути, статус текущей копии и кнопка повторной проверки/создания.

Если запись журнала прошла, а backup не удался, UI говорит об этом отдельно:
решение уже на диске, но копия **не подтверждена**. Не создавай то же решение
повторно; повтори backup или скачай JSON. Если основной save не подтверждён,
сначала обнови журнал: запись могла завершиться до потери ответа.

В конце проверки нажми **«Скачать журнал JSON»** и сохрани файл на другом диске
или в выбранной приватной резервной папке. Локальная копия на том же диске не
защищает от потери всей среды. Вместе с ней сохрани отдельно настоящий XLSX;
snapshot и bundle можно снова получить из него. Журнал содержит имя и комментарии,
поэтому его не нужно отправлять в публичный репозиторий.

Для восстановления останови сервер через Control+C, затем из папки репозитория:

```sh
"./Trainer Review.command" --restore-journal '/полный/путь/trainer-review-journal.json'
```

Если потерян и snapshot, launcher сначала попросит оригинальный XLSX. Restore
проверяет hash chain и привязку к тому же source/bundle. Он восстанавливает
отсутствующую историю или дополняет её точным продолжением. Откат более нового
журнала, расходящиеся решения, повреждённые копии и замена повреждённого текущего
файла автоматически запрещены. В таком случае сохрани оба файла для разбора;
не удаляй текущий журнал и не объединяй JSON вручную. Hash chain выявляет
повреждение, но не является цифровой подписью тренера.

## Проверено в восстановленной среде

Начальная ветка `feature/smart-trainer-catalog-alpha`, коммит
`47e06b9b521ace4898c09843cd81d646d557f410` доступны. Приватного snapshot в новом
checkout не было. В Downloads найден оригинальный XLSX с совпавшим SHA256;
существующий importer восстановил snapshot, исходный catalog hash и pilot bundle
`2df06832f5dff2e8e07fe29e839cc4119dd3c4c474d6acca36a080300d94431c` совпали.
У `raw-cells.json.gz` отличается только служебный gzip OS byte: macOS `0x13`
вместо прежнего Linux `0x03`; из-за его checksum отличается и manifest. Это
проверено сравнением в памяти: при изменении только этого байта получается
прежний SHA gzip, а при подстановке только прежнего gzip hash — прежний SHA
manifest. Приватные файлы при проверке не менялись. XLSX, catalog, audit и HTML
побайтно совпадают, содержимое пилота имеет прежний bundle hash. Importer не
переписывался ради различия заголовка между ОС.
Исторические отчёты аудита не изменены. Приватного журнала прежней среды не найдено;
фактические решения тренера не реконструировались и не создавались.

Браузерный сценарий использует настоящий bundle и отдельный временный журнал
с явно синтетическим reviewer. Он проверяет маршрут, 10/10 после зависимостей,
сохранение gates программы, JSON export, backup, перезапуск сервера, конфликты,
ошибки записи, отсутствие внешних запросов и изменений Mini App localStorage,
ширины 320/390/1280 и WCAG A/AA. [Отчёт Stage 3B](pilot/stage-3b-browser.json).
Это Chromium на macOS, не проверка настоящего Telegram на устройстве.

Итог: 73 Python tests, 319 Vitest tests, build и ESLint прошли; 14 сценариев
Trainer Review и 31 существующая браузерная проверка Mini App прошли.
