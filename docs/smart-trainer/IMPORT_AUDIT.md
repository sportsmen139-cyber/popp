## 2. Подтверждённая кодовая база

В `client/src/data/exercises.ts` действительно 45 уникальных стабильных IDs.
Имена, metadata, resolver, equipment taxonomy и все данные остаются прежними.
Существующий `catalogMigration.test.ts` фиксирует 45 IDs и полные Gym/3
prescriptions, включая порядок A/B/C для уровней и целей. Старая история
продолжает разрешаться непосредственно по прежним IDs, без alias по названию.

`LEGACY_EXERCISE_MAPPING.csv` содержит ровно эти 45 IDs/названий из кода.
Все новые IDs, версии, match_type и confidence пустые, решение `PENDING_SOURCE`.
Это список для review, а не 45 отрицательных результатов поиска: `NO_MATCH`
можно поставить только после исследования доступного источника.

## 3. План проверки после получения snapshot

Сначала зарегистрировать источник по [правилам snapshot](snapshots/README.md).
Нормализованные листы 12–19 и справочники являются данными; обзоры 23–33 и
визуальные циклы 34–141 не создавать как повторные сущности. Названия и состав
вкладок пока известны только из задания и требуют сверки с workbook index.

| Проверка | Где искать | Условие / запись результата |
| --- | --- | --- |
| IDs, составные ключи, версии | 06, 12, 16–18 | Blank/duplicate ID, duplicate `(id,version)`, несовместимые версии → sheet/row/ID/raw value |
| Counts и статусы | 00, 07, 12, 16 | Считать физические непустые строки отдельно от уникальных ключей и публикации; NEEDS_REVIEW/REJECTED не активировать |
| Required fields / инструкции | 02, 12, 13 | Отличать пустое, неизвестное, формулу с пустым результатом, ошибку и явно «не требуется» |
| Taxonomy | 03, 04, 11–14 | Проверять FK и семантику equipment/movement, не переводить по похожему названию |
| Equipment | 11, 12, 14 | OR комплектов / AND предметов; unknown не превращается в equipment-free |
| Биомеханика / мышцы | 12–14 | PRIMARY/SECONDARY/STABILIZER сохраняются; никаких процентов EMG или выводов об активации |
| Prerequisites / иерархии | 03, 04, 12, 14 | Проверять self-FK и недопустимые циклы зависимостей; не объявлять любую встречную замену ошибочным циклом |
| Направленные замены | 05, 15 | FK, A/B/C, контекст, статус; ни обратного ребра, ни транзитивного замыкания автоматически |
| Полные циклы | 16–19 | program/version → phase/week → session → ordered slot; пропущенные/лишние недели, фазы, orphan rows |
| Prescriptions | 09, 16–19 | set/reps/time/distance/RIR/rest с units и mode; противоречия range/fixed/max, неизвестные формы нагрузки |
| Прогрессия / пропуски | 09, 10, 16–19 | Полные условия, пороги, исключения, fatigue/adaptation limits; запрет превращать текст в придуманную формулу |
| Формулы | Все исходные + 20 | Сохранить formula и cached value; отметить stale/missing cache, `#REF!`, `#VALUE!`, ошибки диапазона/локали |
| Недельный объём | 19, 20 | Сравнить объявленный, cached и независимо рассчитанный по явным prescriptions; неоднозначность не округлять до совпадения |
| Источники и review | 20–22 | Проверить references, trainer_comment и решения по строкам; ни наличие строки, ни прохождение schema validation не являются approval |

В отчёте каждого следующего запуска нужны: spreadsheet ID, snapshot SHA256,
captured_at (реальное время), schema/importer version, counts по вкладкам/статусам,
диагностики `(sheet, row, id, field, raw_value, reason)` и reproducible output hash.
Не вычислять формулы самостоятельно как будто это Google Sheets: workbook cached
values сначала сверять с отдельно экспортированными рассчитанными значениями.
