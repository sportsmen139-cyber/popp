# Обратная связь альфа-тестировщиков

## Подготовлено

Кнопка «Обратная связь» находится на главном экране и в unavailable state плана.
Отдельного экрана профиля сейчас нет: «Профиль» вызывает прежнее редактирование
onboarding, и этот flow не менялся. Новый feedback screen не сбрасывает профиль,
счётчик, историю или черновики тренировки. Он доступен до старта тренировки;
в активной тренировке новых переходов с риском потери ввода нет.

Категории: ошибка / улучшение / удобство / свободный отзыв. Есть текст 1–2000
символов и необязательная оценка 1–5 для удобства. Всё хранится только в React
state, при выходе с экрана сбрасывается. История, самочувствие, профиль,
Telegram initData, user ID, телефон, user agent и другие diagnostics не читаются
и не добавляются к сообщению. Диагностическая телеметрия не реализована.

## Настройка перед альфой

Подтверждённого username в задании нет. В `client/.env.example` добавлена пустая
публичная настройка `VITE_FEEDBACK_TELEGRAM_USERNAME`. Владелец должен указать
**подтверждённый username** аккаунта/специального бота без URL, `@` или токена
в frontend build environment. Эта настройка публична. Настоящего значения в Git
нет. Изменение Vite env требует rebuild; приложение не делает config-запросов.

Проверить, что адресат разрешает входящие сообщения от тестировщиков. Для бота
одного username недостаточно: он должен уже принимать сообщения, корректно
работать после Start и доставлять их владельцу. Bot token только на его сервере,
никогда в VITE_* или React. Этот этап не создаёт бота или серверный endpoint.

При отсутствии/ошибке настройки кнопка открытия отсутствует, объяснение видно;
остаётся рабочее копирование подготовленного текста и read-only preview для
ручного копирования при запрете Clipboard API. Ни выдуманного адресата, ни
«успешной отправки» в отсутствующий endpoint нет.

## Handoff, а не delivery receipt

Формируется фиксированный HTTPS `https://t.me/<username>?text=<encoded draft>`.
С Telegram SDK вызывается только `openTelegramLink`; без SDK — browser open
с noopener/noreferrer. Native bridge errors ловятся. Browser popup blocker и
приём сообщения приложением назначения невозможно надёжно подтвердить с клиента;
возврат API не считается доставкой. Статус говорит «Запрошено открытие Telegram…»
и просит проверить адресата и нажать «Отправить» самостоятельно.

Поддержка draft text зависит от Telegram/client/типа чата, особенно у бота.
Поэтому всегда есть отдельное копирование и preview. Нельзя утверждать, что
бот получил сообщение при одном открытии ссылки. Настроенный контакт должен
пройти реальный end-to-end smoke-test до приглашения альфа-тестировщиков.
Telegram может показать профиль отправителя адресату — это явно указано в форме.

В этой реализации нет HTTP send endpoint, поэтому тест «ошибка отправки»
проверяет отказ handoff и Clipboard API, а не фиктивный server delivery error.
Если потребуется настоящая форма с подтверждением delivery, это отдельный backend
этап с подтверждённым endpoint, rate limits и privacy/retention правилами.

## Тесты

Unit tests: конфигурация, encoding/query isolation, пустой/длинный текст,
Telegram SDK handoff, отсутствие SDK, исключение bridge/browser adapter,
отсутствие config, clipboard success/absence/rejection, rating и отсутствие
автоматических profile/history/diagnostic fields.

Browser tests используют только синтетический username в процессе dev server;
все переходы перехватываются, внешние сообщения не отправляются. Проверяются
реальные кнопки формы, ошибки и неизменность трёх localStorage keys.
Manual gate: реальные web/iOS/Android Telegram и подтверждённый адресат.
