## Обязательные препятствия

1. **Dead Bug.** В PRG_000001 исходно 6–10 повторений на сторону с подходами
   1/2/2 по фазам; это назначение не изменено. В PRG_000013 и PRG_000021
   записаны 15/20/25 секунд при REPS в карточке. Требуется отдельное решение
   тренера для этих двух программ. Утверждённые 2×6/8/10 для предыдущей шестёрки
   на них автоматически не распространяются. Точные шесть позиций указаны
   в [отчёте](audit/two-day-preparation.json).
2. **Раздельный учёт сторон.** Существующий исполнитель сохраняет одно число
   повторений на подход. Для EX_000135 во всех трёх и EX_000090 в двух средних
   программах этого недостаточно. Текст «на каждую сторону» не заменяет запись
   обеих сторон. До реализации и проверки этого формата выполнение закрыто.
3. **Оборудование.** У EX_000110/EX_000135 в первой программе и
   EX_000131/EX_000135 в двух остальных структурное оборудование UNKNOWN.
   Решение о нескользкой поверхности для скручиваний/Dead Bug/боковой планки
   уже сохранено; оно ещё не преобразовано в технический контракт. EX_000110
   в него не входит. Программные комплекты тоже обязательны: коврик в исходном
   комплекте программы нельзя убрать молча на основании решения о карточке.
4. **Технический допуск.** Требуются привязанные к точной проекции политики
   цикла/прогрессии, проверка версии Engine и допустимого шага оборудования.
   При конфликте дозировки сначала исправляется согласованная проекция,
   затем фиксируется её hash. Тестовый допуск нельзя переносить в реальные данные.
5. **Контент.** Авторство программ заявлено владельцем и не смешивается
   с правами на заимствованные тексты. Не создано разрешение на распространение
   смешанного исходного пакета. Будущая поставка должна включать только одобренные
   самостоятельные тексты; медиа необязательны и остаются отключёнными.

Не требуется повторное содержательное утверждение всех 108 программ.
Для некорректной структуры отчёт не может вычислить execution hash; это блокирует
весь допуск. После устранения конфликта снова проверяются все остальные условия,
даже если они ещё не перечислены отдельно из-за отсутствия проекции.

## Что реализовано

- Выбор отдельной группы `--batch two-day` в существующем локальном интерфейсе.
  Оригиналы, фазы, упражнения, дозировки, RIR и оборудование доступны владельцу
  для просмотра. Корректировки предыдущей шестёрки сюда не применяются.
- Проверка точного уровня, среды, частоты, цели и специализации. Нет подстановки
  legacy или программы на три дня. Новичку нельзя выбрать средний уровень.
- Переход из допущенного каталога к существующей странице изолированного Engine.
  Проверки допуска повторяются при открытии и каждом запросе. Открытие страницы
  не создаёт назначение; необходимы инвентарь и подтверждение условий старта.
- Существующие журнал, продолжение занятия, результаты, экспорт и переходы фаз
  переиспользованы. Engine уже поддерживает произвольное число исходных дней;
  изменена только подпись ошибки интервала отдыха, алгоритм не переписан.
- В локальной сборке Mini App объясняется наличие соответствующей двухдневной
  программы в подготовке. Назначение не создаётся. Это ещё не исполнение трёх
  реальных программ внутри Telegram.

Синтетический тест проходит 16 завершений в последовательности 1/4 с интервалами
3/4 дня, переходами фаз по существующей политике, сохранением истории и восстановлением
после перезапуска. Пропуск не перескакивает через занятие. Неизвестный инвентарь,
неверный профиль, Origin/Host/CSRF и отменённый допуск не позволяют создать назначение.

## Как посмотреть на Mac

1. В Finder открой папку проекта и дважды нажми **Two Day Programs.command**.
   Используется тот же Python 3.12+ и тот же приватный snapshot, что в Trainer Review.
2. Откроется локальная страница. Выбери «2 дня» и уровень. У новичка появится
   общая подготовка; у среднего — набор массы без акцента и акцент на ноги.
3. Нажми «Посмотреть программу», раскрой фазы и проверь исходные назначения.
   Пока есть препятствия, кнопка тренировки отключена с объяснением.
4. Закрытие окна терминала останавливает локальный сервер. При занятом порте
   можно запустить существующий launcher с `--batch two-day --port 0`.

Просмотр не записывает решений. Новые условия согласуются в чате и затем сохраняются
отдельным версионным решением с исходными значениями. Существующие журналы не удаляются.
После реального допуска записи Engine хранятся в `.local/smart-trainer/trainer-review/journals`;
экспорт на странице относится к выбранной программе. Для резервной копии сохраняется
вся эта папка, а не только HTML. Это изолированный контур, он не переносит историю
пользователей между доменами Alpha.
