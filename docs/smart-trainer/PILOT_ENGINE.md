# Авторская методика и изолированный пилотный Engine

Новый процесс: **авторская программа → техническая проверка → персональное
назначение → выполнение → корректировка**. Владелец сообщил, что ранее выполнил
содержательную проверку источника. Повторная проверка 108 программ, каждой мышцы,
оборудования или 177 технических карточек не требуется.

## Открыть на Mac

Двойной щелчок по **Pilot Engine.command** в папке репозитория. Откроется
`http://127.0.0.1:5188/pilot`; точный порт показан в Terminal. Оставь Terminal
открытым. При занятом порте останови прежний процесс через Control+C либо из
папки репозитория запусти:

```sh
"./Pilot Engine.command" --port 0
```

Python 3.12+ и приватный runtime предыдущего этапа поддерживаются тем же launcher.
При потере snapshot потребуется настоящий XLSX с зарегистрированным SHA256;
данные из памяти не создаются. [Восстановление XLSX на Mac](MAC_TRAINER_REVIEW.md).
Node, Supabase и облачные ключи для локального интерфейса не нужны.

**Trainer Review.command** и `/review` сохранены как вспомогательный инструмент
для спорных случаев и будущих изменений. Его старый полный bundle и карточные
release gates не являются основным процессом нового core-пилота.

## Одно заявление владельца

Раздел «Ранее выполненная проверка владельца» показывает точный source SHA256,
108 программ, 203 упражнения, 200 неисключённых упражнений, исключения
EX_000072 / EX_000095 / EX_000098, известные технические расхождения всего источника
и границы подтверждения. Введи имя, отметь заявление о ранее выполненной проверке
и нажми «Зафиксировать заявление владельца».

Запись хранит reviewer, время UTC, точный SHA, текст заявления и hash показанных
фактов/границ. Для этого источника повтор не нужен; повтор доставки одного
действия идемпотентен. Это отдельный журнал `author-statements.json`.
Никаких 177 индивидуальных approvals, подмены NEEDS_REVIEW или разрешений на
исполнение/распространение это действие не создаёт. Имя заявляется локально;
hash chain не является цифровой подписью или удалённой аутентификацией.

В ходе разработки настоящего заявления от имени владельца **не создавалось**.
Проверки использовали явных synthetic reviewers только в временных каталогах.

## Основной scope без альтернатив

Из прежнего immutable bundle выделяется отдельная execution projection:

- PRG_000002 v1, 10 основных EX, 3 фазы, 9 шаблонов сессий, 45 slots, 8 недель;
- 0 включённых ALT, 0 целевых EX альтернатив, 0 их slot links;
- необходимые справочники программы и основных EX остаются для машинной проверки,
  но не требуют ручного утверждения каждой карточки;
- новый scope hash:
  `3f808180419928c3eff7a980fdb496c27530bffc6c7924c0f5966559aa023d2b`;
- исходный полный bundle, source records и прежний review journal не переписываются.

Требования исходного оборудования, назначений, единиц, структуры, отсутствия
REJECTED, совместимости Engine и прав сохранены. Жёсткий deny-list дополнительно
сохраняет исключение EX_000072 / EX_000095 / EX_000098.
ALT_000476 с другой единицей и оборудование EX_000136 не входят в этот scope
и не блокируют его автоматически. Поддержка seconds/meters не заявлена.

Для будущего отдельного включения подготовленных source ALT есть CLI
`--alternative ALT_ID` (повторяемый), создающий другой scope/hash. Неподготовленная
или неподходящая замена не предлагается в интерфейсе. Обратных/транзитивных рёбер
и поиска по похожему названию нет.

## Что исполняет Engine

Код находится отдельно в `tools/smart_trainer/engine/`, UI — отдельная страница
локального сервиса. Работающие React resolver, Training/Load/Session Engine и
storage Mini App не импортируют этот модуль. Это исполняемая изолированная
реализация с filesystem persistence, а не подключённый production Engine.

Назначение имеет собственные ID, source/scope/program revision, policy snapshot,
часовой пояс, инвентарь, личную редакцию и журнал событий. Текущий слот сохраняет
original EX/version и effective EX/version, source session/slot, phase/week,
instance ID, фактические подходы, RIR/unknown, технику, устройство/настройки,
помощь/стороны, калибровку и причину изменения.

### Цикл и выполнение

Поддержана явная typed policy завершённых микроциклов. Номинальная неделя не
вычисляется из календаря или legacy completedWorkoutsCount. Порядок source days
1/3/5 и семидневный цикл сохраняются: минимум день без силовой тренировки между
посещениями, а между днём 5 и следующим днём 1 — исходный трёхдневный интервал.
Переносы продолжают pending source session без удвоения подходов.

На границах фаз нужна отдельная явная фиксация тренером техники, освоения настроек
и восстановления. Можно удерживать переносимую фазу и повторять её дозу; даты
её не повышают. Нельзя перейти в новую фазу посреди удерживаемого микроцикла и
потерять оставшиеся сессии. После последней сессии недели 8 — `cycle_completed`;
повтор требует нового назначения, старое остаётся в истории.

Подходы сохраняются явно. Пустые reps/resistance/RIR не превращаются в ноль;
явный ноль сохраняется. REPS logger не принимает seconds/meters под другим
именем. Полное завершение требует фактов по непропущенным позициям; остановка
сохраняет уже сделанное без продвижения счётчика.

### Четыре действия с упражнением

**Пропустить сегодня:** действие только в текущем session instance, с причиной.
Другие slots не меняются. Пропуск не создаёт выполненные подходы и компенсацию.
Уже записанные факты не удаляются. Пропуск основной обязательной позиции даёт
`partial`: история сохраняется, успешная сессия и cursor не продвигаются. Позже
возможен новый экземпляр той же сессии после нужного отдыха, с обычной дозой.
Разрешённый source skip дополнительной позиции не создаёт фиктивные подходы.

**Заменить сегодня:** только явный направленный ALT для версии и slot context,
совпадающий с goal/role/level, уровнем/средой цели и полным комплектом инвентаря.
Показываются техника, оборудование, отличия и отдельная новая доза. A/B требуют
подготовленной контекстной записи. Килограммы, калибровка и результаты не копируются.
C не доступна как простая сегодняшняя замена. Если факты уже записаны, их нельзя
переименовать в другой EX. В следующей сессии сегодняшняя замена не наследуется.

**Убрать из моей программы:** отдельная персональная редакция для будущих сессий.
Проверяются source slot scope, обязательные позиции, пустые сессии, номинальный
объём по фазам и мышечные роли. PRIMARY/обязательную позицию автоматически убрать
нельзя: нужна новая согласованная структура. Для прочих позиций требуется точная
оценка влияния, привязанная к hash отчёта и списку source slots. Неизвестные
коэффициенты не достраиваются. Открытая тренировка сохраняет свой snapshot.

**Заменить в моей программе:** prepared ALT + отдельная оценка влияния на все
затронутые slots/фазы и typed назначения цели. C требует явного пересмотра
программы и дозы. Source EX, target EX, версии, дата, причина и личная редакция
остаются в событиях. «Вернуть исходный вариант на будущее» добавляет отмену;
прошлые факты и открытый session snapshot не переписываются.

### Прогрессия

Только предложение после двух последних сопоставимых выполнений: одинаковые
EX/version, исходная роль/позиция, фаза, личная редакция, фактическая доза,
устройство/настройки/помощь/стороны и рабочее сопротивление. Нужны все рабочие
подходы со стабильной техникой, верх **своего** диапазона (в том числе 15/20),
заданный RIR и явная калибровка. Неизвестный RIR не разрешает прибавку.
Минимальный шаг задаётся для конкретного EX/version/context; число подходов
одновременно не растёт. Масса тела ведёт к проверке качества/рычага, не к
автоматическим килограммам. Два сопоставимых выполнения ниже нижней границы
выдают пересмотр восстановления/дозы; автоматического произвольного снижения нет.

## Технические контракты и оставшиеся блокеры

Настоящий scope ещё **не разрешён к исполнению**. В настоящий файл policy не
внесены догадки об оборудовании или фиктивные attestations. Нужны:

1. Одно заявление владельца по источнику через UI.
2. Явные equipment contracts EX_000082 и EX_000135: `explicit_none` либо точные
   kits. Отсутствие строк источника само по себе не означает equipment-free.
3. Подтверждённая typed policy переходов недель/фаз, переносов, прогрессии и
   конкретных шагов устройств. Реализованный вариант completed microcycle —
   поддерживаемая опция, не автоматически принятое решение владельца.
4. Engine report с точным проверенным commit, evidence и core capabilities.
   Пройденные synthetic tests не являются фактическим независимым attestation.
5. Отдельное подтверждение прав распространения. Авторское содержательное
   заявление его не заменяет.
6. Перед реальным назначением — полный фактический инвентарь и исходные
   предпосылки участника. Merge/deploy/rollout требуют отдельного разрешения;
   этого publisher или production activation в инструменте нет.

Приватный policy JSON передаётся через `--technical-contracts '/private/policy.json'`.
Он связан с точными `source_sha256`, `scope_hash`, `policy_version`, reviewer,
timestamp с timezone и evidence; `decision=technical_policy_confirmed`.
Состав контракта определён в `engine/contracts.py`:

- `equipment`: EX@version → явный `state` и, при необходимости, OR kits / AND items;
- `cycle`: `completed_microcycle`, `explicit_trainer`, `resume_pending_with_rest_day`;
- `progression`: `two_comparable_exposures`, `steps` по ключу `EX@version|context`;
- `engine_report`: `engine_supported`, commit SHA и все `CAPABILITIES=true`;
- `rights_receipt`: отдельное `publication_rights_confirmed` с тем же scope;
- `alternatives`: только prepared `ALT_ID:SLOT_ID`, context review, typed доза,
  отдельный `program_change_reviewed` для C;
- `personal_changes`: exact source revision/mode/ALT/slot_ids/impact_hash и
  содержательное evidence пересмотра объёма/структуры.

Браузер не может передать себе эти разрешения в команде. Изменение policy hash
не переписывает прошлое и останавливает продолжение старого назначения до
отдельного решения о версии. В назначении сохранён старый policy snapshot для
восстановления его истории. Fixtures с полностью synthetic receipts находятся
**только в tests** и никогда не загружаются launcher как разрешения реального XLSX.

## Сохранность и восстановление

Source XLSX/catalog/bundle, auxiliary review, author statements, персональные
назначения и три legacy localStorage keys хранятся отдельно. Все 45 legacy IDs
остаются прежними; EX IDs не становятся aliases и не получают старые веса.

Новые журналы append-only с hash chain, operation IDs, optimistic head,
file lock, mode 0600, temporary write + fsync + atomic replace + directory fsync.
Одна команда атомарно сохраняет историю и новый cursor/revision. Повтор доставки
одного operation ID не создаёт дубль. Stale window получает конфликт; повреждённый
журнал не перезаписывается. Backup failure сообщается отдельно от успешного save.

В UI скачай **оба** журнала: заявления и назначения/выполнение. Сохрани их на
другом диске вместе с оригинальным XLSX и, если появится, exact private policy JSON.
Копия на том же диске не защищает от потери всей среды. Ни реальные журналы,
ни полный контент, ни reviewer names не добавляются в Git.

Для восстановления останови сервер и из папки репозитория выполни:

```sh
"./Pilot Engine.command" --restore-author-statements '/private/author-statements.json' --restore-pilot-events '/private/pilot-assignment-events.json'
```

При необходимости добавь прежние `--technical-contracts` и точные `--alternative`
того назначения. Проверяются purpose, chain, prefix и source/scope/policy при replay.
Откат, расходящиеся ветки, повреждение или история другого scope не заменяют
существующие файлы. Восстановление не создаёт activation или новые approvals.

## Проверки

Python: конечные 8 недель/24 сессии, hold/resume, отдых/переносы, skip/partial,
A/B/C и версии, оборудование/units, personal impact/undo, history identity,
прогрессия/unknown RIR/15–20/перекалибровка, disk failure, idempotency, restore,
owner declaration отдельно от technical gates, Host/Origin/CSRF и запрет API bypass.

Браузер проверяет настоящий core scope read-only и synthetic declarations в
**временном** журнале; положительный execution workflow — на явно synthetic
fixture и policy. Настоящее заявление владельца и настоящее назначение не создаются.
Отдельно запускаются прежний Trainer Review и регрессия Mini App.
Отчёты: [engine-browser.json](pilot/engine-browser.json),
[engine-validation.json](pilot/engine-validation.json),
[регрессия Mini App](pilot/engine-miniapp-browser.json).

Итог: 93 Python tests, 319 Vitest tests, build и ESLint прошли; 6 browser scenarios
нового пилота, 14 вспомогательного review и 31 прежней Mini App прошли.
Настоящие права, equipment/cycle/progression policy и Engine attestations
этими тестами не создавались. Native Telegram/device тест и production rollout
не выполнялись.
